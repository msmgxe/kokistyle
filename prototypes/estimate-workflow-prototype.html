Helper: como se gestionaria

  1. El Estimate sigue siendo la fuente comercial: secciones, items, montos y PDF.
  2. El Day Planner solo decide ejecucion: dia, horas y prioridad de trabajo.
  3. Al presionar Generate, cada item asignado crea una fila en tasks.
  4. Workflow gestiona esas tareas con status pend, prog y done.
  5. La task conserva su origen mediante estimate_item_id, para evitar duplicados y permitir sincronizacion futura.

Campos recomendados

ALTER TABLE tasks
ADD COLUMN IF NOT EXISTS scheduled_date DATE,
ADD COLUMN IF NOT EXISTS estimate_item_id UUID REFERENCES estimate_items(id) ON DELETE SET NULL,
ADD COLUMN IF NOT EXISTS source TEXT NOT NULL DEFAULT 'manual',
ADD COLUMN IF NOT EXISTS source_section TEXT,
ADD COLUMN IF NOT EXISTS amount NUMERIC(12,2) NOT NULL DEFAULT 0;

Con esto la app puede saber si una tarea vino del Estimate, en que fecha cae y cuanto representa.

Decision de producto

  • Simple: crear tasks por item sin migracion, usando solo name, hours, status y sort_order.
  • Recomendado: agregar scheduled_date y estimate_item_id para trazabilidad.
  • Avanzado: permitir re-sincronizar cuando cambie el Estimate sin pisar tareas ya trabajadas.
